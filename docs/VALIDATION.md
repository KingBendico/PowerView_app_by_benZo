**Validation — PowerView desktop, motion, appearance and shortcuts, 17 September 2026**

The supplied local application is the baseline for this work. The corrected [evaluation](EVALUATION.md) distinguishes its existing features from remaining defects and future ideas.

- `npm run check`: all application, script and test JavaScript parses; referenced UI resources exist.
- `npm test`: 46 focused tests pass. Coverage includes finite requests, HTTP failures, malformed responses, cancellation, secondary-gateway rejection, per-home favorites, configuration recovery and legacy migration, partial group failures, Stop during movement, SSE chunking and subnet boundaries. Motion tests cover stale reads, late acknowledgments, event ordering, missing/invalid travel times, connection loss, simulated travel, intermediate Stop and per-home appearance persistence without motor commands. Curtain coverage includes both single-draw directions, paired geometry, existing-settings migration, demo mechanism changes and restoration, persistence across reconnection, pending-command handling and preservation of real hardware controls.
- `npm run smoke`: 29 native Electron checks pass on macOS arm64 with Electron 44.4.1. The test uses a temporary profile, demo data and a loopback HTTP/SSE fixture. It covers renderer isolation, percentage presets, numeric entry, stable drag targets during refresh, pointer cancellation, continuous demo travel, intermediate Stop, saved curtain appearance, horizontal curtain dragging, type 9 dual rails, keyboard controls, pinning, scene activation, navigation races, modal focus, dark theme, narrow/zoomed layouts, command search and Escape behavior, HTTP errors, acknowledgments, SSE updates and invalid IDs. Bedroom left explicitly switches to curtains, tests both single-draw directions and keyboard movement, and resets to two rail controls. The HTTP/SSE fixture also verifies travel-time animation, stale-read protection and settlement at the final reported position. No renderer errors were recorded. [Machine-readable results](native-smoke-results.json).
- Shortcut coverage adds canonical key validation, per-home persistence, unsupported targets, registration conflicts and failed-save rollback, stale callback rejection, offline behavior, repeat suppression, independent Stop, partial failures, native key recording, actual OS registration, background demo action routing, enable/disable and app/editor visibility cleanup. The editor is also checked at 360px width with Save kept visible. Physical OS key delivery into another focused app is not automated; see [shortcut details](SHORTCUTS.md).
- `npm audit`: the upgraded lockfile had zero reported vulnerabilities when checked on 16 September 2026; dependencies are unchanged in this increment. The original local baseline had 27 affected package entries; its audit is retained separately. Audit counts are not a security certification.
- `npm run package`: generated a macOS arm64 app bundle under `release/PowerView-darwin-arm64/PowerView.app`. It uses local resources and an ASAR archive. No signed/notarized installer is being published.
- Native [Home](screenshots/home-light.png), [dark room](screenshots/room-dark.png), [narrow room](screenshots/room-narrow.png), [moving shade](screenshots/shade-moving.png), [appearance editor](screenshots/appearance-editor.png) and [single-draw curtain editor](screenshots/single-draw-editor.png) captures were inspected. The new [shortcut editor](screenshots/shortcut-editor.png) and [narrow editor](screenshots/shortcut-narrow.png) are captured from the native app.

The original source directory remains unchanged. The app name and user-data identity remain PowerView. The legacy prefs file is retained during migration. Demo launched with `--demo` uses a separate profile; the preview opened for review uses an explicit temporary/workspace profile.

Physical movement has not been tested. Animation between gateway reports is an estimate based on an optional gateway travel time; it is not continuous position telemetry. Without that time, only reported positions advance the graphic. See [motion and appearance details](MOTION_AND_APPEARANCE.md). Broader type mappings, tilt/overlapped/top-down geometry, real discovery across networks, Swagger startup, device battery interpretation, sleep/resume, tray interactions on each OS, Windows/Linux builds and macOS distribution signing still need field/platform checks. The automated tests validate protocol handling and simulated behavior, not a real motor or every firmware version.

Routes and capability mappings were cross-checked against the [aio-powerview-api reference](https://github.com/sander76/aio-powerview-api/blob/master/aiopvapi/resources/shade.py), its [scene resource](https://github.com/sander76/aio-powerview-api/blob/master/aiopvapi/resources/scene.py) and [Home Assistant integration documentation](https://www.home-assistant.io/integrations/hunterdouglas_powerview/). The reference is guidance rather than proof of hardware compatibility. Renderer isolation follows [Electron's guidance](https://www.electronjs.org/docs/latest/tutorial/security).

The draft is version `1.1.0-beta.4` to make its field-validation status clear. The pull request integrates the current local app, reliability work, desktop redesign, smoother movement, per-device appearance settings single-draw curtains and custom global shortcuts. Scheduling, scene previews and automation remain future work.
